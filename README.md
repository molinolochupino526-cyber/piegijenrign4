# Генератор обучающих видео из Markdown-билетов

Скрипт превращает текстовые билеты (`.md`) в вертикальные видео 1080×1920 с
озвучкой и «караоке»-субтитрами поверх геймплейного фона — формат Shorts/Reels/TikTok.

```
MD-билет  ──►  разбиение на части  ──►  TTS (MP3)  ──►  SRT с таймкодами слов  ──►  MP4 9:16
 ~15 000                ~3 000                                                     1080×1920, 30 fps
 символов              символов
```

## Что в кадре

```
┌──────────────────────────────┐
│                              │  ← зацикленный геймплей, затемнён на 25 %
│   предыдущее предложение     │     кегль 30, прозрачность 0.5
│                              │
│   ТЕКУЩЕЕ ПРЕДЛОЖЕНИЕ, ГДЕ   │     кегль 60, слово подсвечено жёлтым
│   ПОДСВЕЧЕНО ОДНО СЛОВО      │     (кегль уменьшается, если текст не влез)
│                              │
│   следующее предложение      │     кегль 30, прозрачность 0.5
│                              │
│ ▓ Билет: … | Часть 1 из 5 ▓  │  ← полупрозрачная плашка
└──────────────────────────────┘
```

Субтитры **не бегут строкой**: блок предложения стоит на месте, движется только
жёлтая подсветка слова. Смена предложений — через плавный fade in/out.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # и вписать ключи API
```

Нужен **ffmpeg**: либо системный, либо пакет `imageio-ffmpeg` (ставится из
`requirements.txt` и приносит свой бинарник).

Положите вертикальное фоновое видео (геймплей Minecraft / Subway Surfers)
в `assets/background.mp4` — или укажите свой путь через `--background`.

Шрифт должен содержать кириллицу. По умолчанию ищется DejaVu Sans Bold;
свой путь задаётся переменной `FONT_PATH`.

## Запуск

```bash
# Посмотреть разбиение на части, ничего не генерируя
python generate.py --plan

# Проверить вёрстку субтитров без расхода квоты TTS (вместо голоса — тишина)
python generate.py --only bilet_1 --part 1 --dry-run

# Полный прогон по всем билетам из tickets/
python generate.py

# Только озвучка и SRT, без рендера видео
python generate.py --audio-only

# Резать по объёму (~3000 символов), игнорируя авторские маркеры «ЧАСТЬ N»
python generate.py --split-mode chars

# Другой голос и провайдер
python generate.py --provider azure --voice ru-RU-DmitryNeural --speech-rate +12%
```

Результаты:

```
output/
├── audio/  bilet_1_part_1.mp3            озвучка части
├── srt/    bilet_1_part_1.srt            таймкоды (по словам или по предложениям)
└── video/  bilet_1_part_1_final.mp4      готовое видео
```

Готовые файлы повторно не генерируются — прерванный прогон можно просто
перезапустить, он продолжит с места остановки. Полная перегенерация: `--force`.

## Разбиение на части

| Режим | Поведение |
|---|---|
| `auto` (по умолчанию) | если в файле есть строки-маркеры `ЧАСТЬ 1`, `ЧАСТЬ 2`… — части берутся по ним; иначе текст режется по объёму |
| `chars` | всегда резать по `PART_TARGET_CHARS` (≈3000) символов, по границам предложений |
| `markers` | только по маркерам; если их нет — откат к `chars` |

Разрез всегда проходит по концу предложения. Количество частей подбирается так,
чтобы они были примерно равного объёма и последняя не оказалась огрызком.

Название билета берётся из заголовка `# …`, строки вида `Билет 1. Название`
или первой содержательной строки файла.

## Синхронизация субтитров

Fish Audio и Azure не возвращают word-level таймкоды вместе с MP3, поэтому
длительность аудио распределяется между словами пропорционально их «весу»:
длина слова + надбавка за знаки препинания (на них диктор делает паузу) +
надбавка за цифры (`2024` произносится как четыре слова). Практический
рассинхрон — десятые доли секунды, для подсветки этого достаточно.

Если нужны точные таймкоды, получите SRT внешним инструментом (например WhisperX)
и положите рядом — модуль `ticket_video.subtitles.parse_srt` читает готовый SRT.

`SRT_MODE=words` — один субтитр на слово (для караоке), `sentences` — на предложение.

## Провайдеры озвучки

**Fish Audio** — основной. `FISH_VOICE_ID` — это `reference_id` голоса из
библиотеки Fish Audio; без него используется голос аккаунта по умолчанию.

**Azure Speech** — резервный: включается автоматически, если Fish Audio
вернул ошибку (отключается флагом `--no-fallback`). Поддерживает стили
произношения через `AZURE_STYLE` (`newscast`, `calm`, …).

Повторы при сбоях: 4 попытки с задержками 2 / 4 / 8 / 16 секунд плюс случайный
джиттер. Повторяются только сетевые ошибки, 429 и 5xx; при 401/403 попытки
прекращаются сразу — ключ всё равно не исправится сам.

## Параллелизм

| Этап | Настройка | Значение по умолчанию |
|---|---|---|
| Озвучка (сеть) | `TTS_WORKERS` / `--workers` | 4 |
| Рендер (CPU) | `RENDER_WORKERS` / `--render-workers` | 2 |

Рендер видео упирается в процессор, поэтому потоков там меньше: ставить их
больше, чем физических ядер, смысла нет — кодирование только замедлится.

## Настройки

Все параметры читаются из `.env` (см. `.env.example`): размеры кадра и fps,
кегли и цвета, прозрачность соседних предложений, цвет подсветки, высота и
прозрачность плашки, пресет и битрейт ffmpeg, пути к каталогам.

## Структура проекта

```
generate.py              CLI: разбор аргументов и запуск пайплайна
ticket_video/
├── config.py            конфигурация из .env
├── splitter.py          чтение MD, очистка разметки, предложения и части
├── tts.py               Fish Audio + Azure, retry с backoff
├── subtitles.py         таймкоды слов и генерация SRT
├── video.py             MoviePy: фон, караоке-субтитры, плашка, рендер
├── pipeline.py          оркестрация этапов и пулы потоков
└── utils.py             логирование, retry, slug, длительность аудио
```

Поддерживаются MoviePy 2.x (рекомендуется, текст рендерится через Pillow) и
1.0.3 — различия в API изолированы в слое совместимости в `video.py`.
Для ветки 1.0.3 дополнительно нужен ImageMagick.

## Производительность

Рендер примерно в 5–10 раз медленнее реального времени на слабой машине:
часть на 2,5 минуты — это порядка 15–20 минут кодирования. Ускорить можно так:

* `FFMPEG_PRESET=veryfast` — быстрее, файл чуть больше;
* `VIDEO_FPS=24` — на четверть меньше кадров;
* прогонять этапы раздельно: сначала `--audio-only`, потом рендер.
